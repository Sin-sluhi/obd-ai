## 1. Что сделано в коде (всё в main)

- **Правило «сначала база»** — продуктовое правило №6 в CLAUDE.md. `KbFirst.gap(snap)`: если все коды проверки разобраны
  подробно и пары кодов двигателя из разных узлов связаны — `Diagnosis.local(snap, complete = true)` (флаг `fromKb`,
  без плашки «офлайн»), иначе нейронка.
- **Подробная база** `tools/dtc/detail/pNN_*.py`: 852 общих + 422 марочных (Лада 167 полных записей, УАЗ/ГАЗ 60 —
  новый `brandKey` `uaz_gaz`, Hyundai/Kia 49, Toyota 48, Ford 28, Nissan 20, GM 19, Honda 16, VAG 15). Поля:
  e (что происходит), sy (симптомы), c (причины с проверкой), ck (проверки с цифрами), d (порядок ремонта), x (ложные
  пути), rk (риск), p, s, stop. Проверка `python tools/dtc/detail/validate.py`, сборка `python tools/dtc/gen.py`
  (`merge_detail`, `merge_links`). Связи семейств для частых пар — `tools/dtc/links_extra.py` (146 направлений).
  На 30 типичных сочетаниях база закрывает 29; демо уходит в нейронку из-за B1602 (кода нет в справочнике).
  Написано по общим знаниям, без ссылок на форумы; ссылки — только из `docs/kb.json`. dtc_ru.json ≈ 5 МБ.
- **Надёжность нейронки** (`AiClient`, `OpenAiClient`, `ForumSearch`): поиск по форумам параллельно, ≤ 35 с, кеш 6 ч,
  при капче DuckDuckGo 15 мин сразу Bing; при 429 читаем «try again in Xs» из тела (заголовка у Groq нет) и ждём ≤ 30 с
  с отсчётом `ai_stage_wait`; таймаут ответа Groq 90 с; одинаковая проверка (VIN + коды) час берётся из кеша; время
  этапов в журнале.
- **Флаги** (`ui/LangMenu.kt`): растр ×2 + `drawBitmapMesh`, скругление, кромка, складки; у KZ/KG солнце с лучами.
- Новые ключи i18n: `ai_stage_wait`, `kb_*` (ru, en; остальные языки берут русский).

**Не проверено на телефоне:** правило «сначала база», ожидание лимита, кеш, флаги. Первым делом — лог консоли после
проверки (строки «Разбор из базы знаний», «В базе знаний нет: …», «Разбор взят из проверки N мин назад», «Поиск по форумам: N с»).

## 2. Лимиты Groq (на один ключ = на всех пользователей сразу)

gpt-oss-120b: 8 тыс. токенов/мин (вместе с max_tokens), 200 тыс./день. Разбор ≈ 5,5–7 тыс. токенов →
~1 разбор в минуту, ~30–35 в день на основной модели + ~30 на запасной qwen. Тот же ключ ночью тратит `kb.yml`.
Ключ встроен в APK и извлекаем — план: свой сервер с ключом (Play Integrity, лимиты на устройство, кеш).
Подписку Claude в приложение не встраивать (правила Anthropic, токен в APK = чужой доступ к аккаунту). Для личного
сравнения моделей — свой ключ API в dev-сборке или прокси через Claude Code на ПК (не сделано).

## 4. Ответы покупателям (что приложение умеет на самом деле)

- **Скрутка пробега:** читается только стандартный PID A6 из блока двигателя (обычно машины ~2019+), сравнивать с
  приборкой. Блоки BMW (CAS/FEM, приборка, коробка) не сравниваются — нужен заводской протокол BMW. Косвенно: недавнее
  стирание ошибок, км с Check Engine, чужой VIN в блоках.
- **«По OBD только моторник»:** на CAN приложение опрашивает другие блоки по UDS (29 типовых адресов + полный перебор у
  Hyundai/Kia; на Tucson 2019 ответили 10). BMW — блоки за шлюзом со своей адресацией: реально двигатель (+ коробка).
- **Кодирование BMW/VAG:** нет (только чтение и стирание ошибок). Покупателям не обещать того, чего нет.
  План, если владелец решит: шаг 1 — чтение и расшифровка кодировки VAG MQB (безопасно); шаг 2 — включение/выключение
  проверенного списка функций с резервной копией и откатом, только после проверки на живой VAG. BMW F/G через
  Bluetooth-ELM327 не делать (нужен ENET). Подушки/ABS/экологию/ремни — никогда.
- **Launch на Android:** APK встанет при Android 8.0+ и разрешённой установке из файла; работать — только через наш
  ELM327, родной VCI Launch не поддерживается.
- **Китайцы:** VIN определяется (Chery/Exeed/Omoda, Haval/Tank, Geely, Changan, JAC/Москвич и др.), стандартные коды
  разбираются подробно, 7 болячек моделей; заводских кодов китайских марок и опыта владельцев нет, на живой машине не
  проверено.
