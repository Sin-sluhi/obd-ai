## Ситуация

Android-приложение (Kotlin) для диагностики через дешёвые Bluetooth-адаптеры ELM327 (клоны «v1.5» на PIC18F25K80 и
«v2.1», реже OBDLink/vLinker). Задача — как у любого базового сканера: подключился, определил шину, **нашёл все блоки
машины, не зная марки заранее**, прочитал память ошибок из каждого. Без записи в блоки, без кодирования.

На полевых тестах версия с фиксированным списком адресов провалилась: BMW F01 (блоки за шлюзом 0x6F1 с расширенной
адресацией), Audi A8 D3 (не-OBD блоки на VW TP2.0), новая Honda (29-битный CAN, `ATSH 7DF` до определения протокола
всё ломал). Бесплатный Car Scanner на той же BMW прочитал 105 блоков.

## Что уже сделано (оцени и найди дыры)

1. Режим `ATH1 ATCAF1 ATS1`, каждый CAN-кадр разбирается с ID, сборка ISO-TP по ID ответа в приложении.
2. Перебор 11-битных адресов 0x700–0x7FF (кроме 0x7DF и 0x7E8–0x7EF) с открытым фильтром `ATCF 700` / `ATCM 700`;
   зонд на каждый адрес — сразу `19 02 FF`; любой ответ (данные, первый кадр, `7F 19 xx`) выдаёт блок и ID его ответа —
   так узнаются смещения +8, +0x6A (VAG MQB), +0x20 (Renault/Nissan), −0x20 (PSA, диапазон 0x680–0x6FF, фильтр 0x600),
   +0x400 (GM, 0x240–0x25F, фильтр 0x400).
3. 29 бит: `ATCP 18`, `ATSH DAxxF1` для xx = 00..FF, фильтр `ATCF 18DAF100` / `ATCM 1FFFFF00`.
4. Дочитывание найденного блока: `ATSH req`, `ATCRA resp`, `ATFCSH req`, `ATFCSD 30 00 00`, `ATFCSM 1`; `7F 19 78` →
   ждать и повторить с `ATST FF`; `7F 19 22/7E/7F` → `10 03` и повтор; `7F 19 11/12` или молчание → KWP `18 02 FF 00`,
   затем `18 00 FF 00`; VIN и номер блока — `22 F190` / `22 F187`.
5. BMW: `ATSH 6F1`, `ATCEA xx` для 0x00–0x7F, `ATCRA 6xx`, `ATFCSD xx 30 00 00`; коды трёхбайтные hex (130508).
6. Toyota: `ATSH 750`, `ATCEA sub`, `ATTA sub` (чтобы фильтр ELM по первому байту пропустил ответ с подадресом), ответ 0x758.
7. K-line (протокол 5): `ATSH 81 xx F1`, `ATFI`, `18 00 FF 00` по адресам 10, 11, 12, 17, 18, 28, 29, 40, 58, 60.
8. Кеш найденных адресов по VIN; стенд с моделью машины в unit-тестах.

   отправляет ли ELM автоматический flow control на «ответ−8» при открытом фильтре и мешает ли это; корректно ли
   `ATCEA` + `ATTA` для Toyota 0x750 (что реально стоит первым байтом в ответе с 0x758); печатает ли ELM байт
   расширенного адреса в ответе при `ATH1`.
2. Полная и проверенная таблица пар запрос/ответ для **Mercedes-Benz** (W204/W212/W205/W222/W166/W176/W246, 2008–2020)
   через разъём OBD: ID, смещение, сервис чтения ошибок (KWP `18 02 FF 00` или UDS `19 02`), нужна ли сессия. Если
   открытой таблицы нет — скажи прямо и предложи, как её узнать перебором.
3. То же для **китайских марок** на рынке России: Haval/GWM, Chery/Omoda/Jaecoo/Exeed, Geely/Belgee, Changan, Jetour,

5. **GM GMLAN**: формат ответа на `A9 81 12` (UUDT на 0x5xx) и на каких ID ждать ответ; какие модели в России (Cruze,

6. **Лада**: адреса блоков на K-line кроме двигателя (ABS Bosch 8.1/9.0, подушки, иммобилайзер АПС-6, электропакет),
   строки init для Январь 5.1/VS 5.1/Bosch M1.5.4; на CAN — Vesta/Granta FL/Niva Travel: ID блоков помимо 0x7E0.
7. Какие ещё марки из топ-30 парка России ломают схему «перебор 0x700–0x7FF + 29 бит + шлюзы BMW/Toyota»:
   приведи конкретные случаи с ID.
8. Типовые причины «блок двигателя не отвечает» у Honda/Toyota/Mazda 2015+ на клонах ELM327 и как их обходят

9. Порядок действий при подключении, который максимизирует шанс найти шину с первого раза (ATZ → … → первый запрос),
