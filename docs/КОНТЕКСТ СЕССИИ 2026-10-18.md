2. Коробка `7E1` ответила `7F 19 78` и не дочитана — ждать дольше.
3. Блоки с `7F 19 31` / `7F 19 11` (Grandeur 700/780/796/7F1) — пробовать другие варианты запроса.
4. BMW/MINI 0x00 = кузовной блок (JBBF на F01 по дампу с форума, JBE на R56).

   61 АКБ), а наша проверка останавливается, когда 7DF молчит. Если шина жива (NO DATA, не CAN ERROR) — продолжать к поиску
   блоков; без VIN пробовать TP2.0 на адресе 01. Добавить VAG-адреса 0x06, 0x1E, имена 34/55/61. Пересчёт VAG P1xxx:
   код = 17408 + последние три цифры (17964 = P1556), P0xxx = 16384 + цифры.

## 3. Следующий большой шаг — «логи сами» (план владелец одобрил по смыслу, начинать с шага 1)

1. **Автоотправка логов** после проверки (галочка согласия при первом запуске; VIN обрезан до марки и года, без
   геолокации) на сервер владельца; сводка по моделям: где опрос споткнулся. ~день.
2. **Ступеньки повторов** внутри проверки: не понял → другой диалект, «подожди» → ждём, не влезло → дочитываем,
   двигатель молчит при живой шине → идём дальше. Частично есть.
3. **Профили моделей с сервера** (адреса, способ связи, имена, расшифровки) — файл раз в сутки, как `kb.json`, подписанный;
   сервер запоминает, какой способ сработал на модели, следующий владелец получает его первым. 2–3 дня.
4. **Самоисправление результата**: хранить сырые ответы машины с проверкой, при новых знаниях переразбирать без
   подключения — «результат по вашей машине обновлён». ~2 дня.
Защита: с сервера только данные и команды чтения из белого списка; каждый лог автоматически прогоняется на стенде.

## 5. Правила работы, которые владелец сформулировал в этой сессии

- Фото, видео, ссылки — **контекст для общей картины**, а не задание чинить всё на них сразу: понять, кратко сказать, договориться.

  механизмами нельзя — приложение только читает, зато…».
